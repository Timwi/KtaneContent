On the Subject of 6-Bit Assembly

Thought Markscript was tedious? Check this thing out! Well, at least it has a lot more commands...

This module uses ☼ as prefix of octal values. Every byte is 6 bits and every word is 2 bytes.

This module consists of 3 screens: Data screen, Command screen, Binary screen; and 2 buttons: 0 and 1.

Initially, the data screen shows 64 bytes of the DATA block and also 64 bytes of the COLOR block. COLOR is immutable. If you hover over the symbol in DATA block, the Command screen will show you the word that consists of the DATA byte in higher byte of word and the COLOR byte in lower byte of word.

Pressing the Binary screen will show you the PROG0 block, whopping 64 words of memory for your very own program! That’s not enough for you? Don’t worry! Pressing the Binary screen when the current input is 1 will send you to the other program block, because there’s two of them. There’s also PROG1 - another 64 words of memory!

While seeing PROG0/PROG1, you may input the opcode for a desired command. When you finish inputting the 12-bit string, module will show you the assembly command for your opcode. After that, press 1 to accept the input and insert/replace the command, or 0 to cancel the input. However, if the opcode is not valid, then module will show its octal value with a question mark (for example: ☼3300?).

To go back to DATA, press Binary when the input is empty. To clear the input - press Command. However, if you try to clear the input that is already empty, you will change the insertion mode (INSERT/REPLACE), where the default is REPLACE. To delete the command at the cursor, press Binary when the input is 0. To run the code, press Command when seeing DATA. To stop running, press Command again.

Your goal is to write some code that not only successfully completes the task, but also safely stops the program by going into an infinite loop (the easiest solution for that is RJMP ☼00 in the place where you want to stop the program). Remember that if the CPU goes out of either block or meets an unknown opcode, the module will strike. These are the only 2 cases of the module striking. THE CPU IS NOT GOING TO AUTOMATICALLY JUMP TO PROG1 IF IT GOES BEYOND ☼77 AT PROG0!

Parameters

Everything is zero-indexed in this section.

Take the column at the position of the zeroth vowel in the serial number, otherwise - the zeroth even digit of the serial number, otherwise position 6. From this column, take only the COLOR bytes from top to bottom. The zeroth byte modulo <number of tasks - 1> is the task number. Don’t forget to convert to decimal. The first through the seventh bytes are called the parameters for the task. Going from top to bottom from the first byte, if that byte modulo ☼10 is equal to any previous byte modulo ☼10, then add ☼01 to current byte and modulo it by ☼100. If any parameter is equal to ☼00, add ☼10 to it.

R0-R7 are the registers that store some values, A* refers the address (☼00-☼77), V* means the constant value (☼00-☼77), N* also means some constant, it’s ☼00-☼77 unless stated otherwise. Data[A*] means the byte of DATA at address A*. All values mentioned in a statement are the initial ones (before the program runs), unless stated otherwise. The ranges of bytes wrap around: the byte after ☼77 is ☼00.

*a means that the value is taken from the zeroth parameter, *b - from the first parameter, ..., *g - from the sixth parameter.

To get the variable in its range, modulo it by the number of possible values for this variable and add the smallest possible value for this variable, unless stated otherwise.

Notes on architecture of CPU

Each opcode is 1 word long, no exceptions. P is the value that is stored inside the R7 register and used as address.

Flags are stored inside their own register. There are three flags:

  • Z - Zero flag. Sets when the resulting value equals to ☼00.
  • C - Carry flag. Toggles when the overflow or underflow occurs.
  • N - Negative flag. Sets when the resulting value is more than ☼37.
